Inside the workflow

Illustrative reconstruction · No workplace data

01 / Source context

Start with the sources.

I checked Jira against RFCs, GitHub, and Slack for missing decisions. Conflicts and unanswered product questions stayed visible.

What this stage protects

Missing context stays visible.

Unavailable, empty, and disconnected sources had to stay distinct.

02 / Preparation

Choose the check before the tool.

The runbook separated checks for stored values, server rules, and interface calculations.

A test-layer decision

BMI needed UI coverage.

Stored vitals needed GraphQL checks; BMI calculated in the interface needed UI checks. Test design and limits.

03 / Investigation

Follow the state beyond Save.

Toggling and saving one setting dropped other choices. I compared recordings, HAR logs, and GraphQL values before and after reload, using an unaffected option as a control.

What this stage protects

A persistence claim needs readback.

I recorded actions, requests, reloads, and saved values separately, with the testing environment labeled.

04 / Independent review

Try to disprove the claim.

An independent AI reviewer replayed form logic against recorded requests. I corrected claims the evidence did not support.

A correction this stage caught

A loading screen was labeled as a saved result.

The notes kept timing offsets, missing visuals, and unwatched recordings visible.

05 / Human decision

Write the verdict with its limits.

I wrote the acceptance verdicts; AI assembled the surrounding prose. Preparation, investigation, independent review, and my decision stayed separate, with review before posting.

What this stage protects

Dev coverage stays labeled dev.

I corrected a dev check labeled staging and added a source check after a shortened comment overstated the notes.

Reconstructed workflow, not a workplace artifact. Historical coverage limits remain attached.

Test design

Put the assertion in the right place.

I put stored vitals and server rules in GraphQL tests. BMI calculated in the interface needed UI coverage.

Early June 2026 records show dev API checks run and UI checks pending. Later June API and Playwright runs record failures, deferred checks, and local-versus-dev differences.

In October 2026, I required readings created through the UI in one test tenant. Review made the seed-write guard check the selected tenant, not a requested argument. A build marker checked what the browser actually served.

Workflow refinement

Sometimes, remove a stage.

I retired a parallel-work pipeline with too much overhead and moved an unused impact viewer into a screen I used.

I switched Kanban lanes to pipeline stages and removed misleading sample cards. One writer per shared document and interruption recovery steps kept handoffs manageable.

Sustained maintenance · June–October 2026

Keep the tracker honest.

A June refinement surfaced work hidden by a project filter and separated tag-cut dates from deployment dates. The running application could still lag behind the deployment API.

In July, the publishing wrapper gained wake-error retries and a guard against publishing stale source data. The generator produced dated records in October; that does not prove every scheduled publish succeeded.

Review in practice

After a repaired pilot passed its sample, I asked for more random trials.

Outputs

Useful work, with the limits attached.

The workflow produced runbooks and evidence reviews. I combined Jira, GitHub, and release discussions into Google Docs and Confluence updates. I operated the tools; colleagues followed releases through the documents. Read the release-readiness case.

Limits and lessons

Keep the unfinished work visible.

This was personal QA tooling. In September 2026, I retired demo-document polling, then the changelog Google Docs poster. The markdown generator and Confluence publishing were unaffected. I corrected stale information and environment mix-ups; later work covered coverage review, browser harnesses, and CI triage. These records do not establish complete current care-module coverage.

A useful packet lets me start work and see what remains unchecked.
